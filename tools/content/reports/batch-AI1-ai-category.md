Spec: `tools/content/specs/ai-all.json` (44 Commons `cat:` topics: 25 generator categories + 19 subject/genre/style

### Tooling issue found (not fixed, reported here)

`run.sh pool ai-all` first run: topic `cat:Images generated by DALL-E` listed 516 files, 231 passed the prefilter, 0 usable:
all 231 came back `http 429` from Commons' thumbnailer (1200 px renditions of uncached PNG originals are throttled at a
few requests per second; another worker's pool was running at the same time). Two problems in `cjw/imagecache.py` /
`cjw/pool.py`:

- `fetch()` has no backoff or retry on HTTP 429 and `fetch_many()` runs 4-8 parallel workers, so a throttled run marks
  every candidate `bad`; the pool keeps those URLs in its `have` set and never retries them.
- `fetch()` gives up for good after `tries >= 2`, so a second throttled run locks the URL out permanently.

Workaround used: purged the 231 `http 429` candidates and their meta files from the pool (scratchpad `purge429.py`),
then pre-warmed the meta/thumb cache sequentially with exponential backoff on 429 (scratchpad `warm.py`, using the
tooling as a library, no code changes) before re-running `pool ai-all`, which then only hits the cache.
